# M1 plan: `:bmap` library

Branch `m1-bmap`. First commit (`Apply M0 review notes`, already pushed) applies the M0 review. One PR into `main` at the end.

## Context

M0 settled the protocol facts on the real device and captured fixtures. M1 builds the pure-JVM library that M2's service sits on: typed parsers and builders for every feature-map row, a `BmapConnection` with request/reply matching over an abstract byte transport, mode-profile logic ported from bosectl, and `FakeBmapDevice` so M2/M3 can be tested without the phone. No Android code, no device run.

## Design

All under `bmap/src/main/kotlin/io/github/sargemck/practicalheadphones/bmap/`. Existing `BmapFrame`, `BmapOp`, `FrameParser`, `Hex` are reused unchanged.

### 1. Transport and connection

- `FrameTransport` (name from PLAN; carries raw bytes, the connection does the framing):
  `suspend fun read(): ByteArray?` (null = closed by the other side, i.e. `read() == -1`), `suspend fun write(bytes: ByteArray)`, `fun close()`. An `IOException` from either is a disconnect. M2's `RfcommTransport` wraps the socket streams.
- `BmapConnection(transport, scope, logger)`:
  - `start()` launches the one reader coroutine: `read()` → `FrameParser.feed` → dispatch each frame. Skipped bytes are logged.
  - `request(frame): BmapFrame` behind a `Mutex` (one in flight). Completes on the first frame with the same `(fblock, func)` and op STATUS / RESULT / ERROR. PROCESSING restarts the 3 s timer, with a 10 s cap on the total wait per request; hitting the cap counts as a timeout. ERROR throws `BmapException.DeviceError(address, code)`.
  - `drain(frame): List<BmapFrame>` for START 31.1. Completes on `31.1 RESULT`. Fallback: 500 ms after the last frame. 3 s for the first frame. Every fblock-31 frame that arrives during the drain belongs to it (the M0 fixture shows 31.0, 31.2, 31.3, 31.6 ×11, 31.8, 31.10, 31.11 before the RESULT). If an address repeats, the last value wins. Non-31 frames go to unsolicited.
  - Any frame that doesn't belong to the in-flight request goes to `unsolicited: SharedFlow<BmapFrame>`, never to a caller.
  - Timeout handling:
    1. Retry once on timeout. All our writes set absolute values, so a repeat is harmless.
    2. If the retry also times out, send a liveness check, GET 2.2.
    3. If 2.2 answers, the address is unsupported: throw `BmapException.Unsupported(address)` and keep the connection open (the [31.4] case).
    4. Only if the liveness check also times out: throw `BmapException.Timeout` and close with `Closed(Unresponsive)`. M2 decides any reconnect under the connect rules.
  - Power off [7.4] and pairing [4.8] are never retried. The device drops the link after accepting them, so a disconnect within 3 s of sending counts as success.
  - Known limit (documented in KDoc, no handling): a reply that arrives after its timeout could be matched to a later request to the same address. Unlikely with a 28 ms median reply against a 3 s timeout.
  - No raw send in the public API. Only features defined in the device config can be sent; free-form send stays in the debug spike.
  - `state: StateFlow<ConnectionState>`: `Open` or `Closed(reason)`, with reason `RemoteClosed` (read returned null), `IoError`, `Unresponsive` (retry failed) or `Local`. M2 needs `RemoteClosed` for the contention rule. A disconnect fails the in-flight request with `BmapException.Disconnected`.
  - Hard-rule guard before every write: only GET, SETGET and START, and never fblock 18. Anything else throws `BmapException.Refused` and no bytes are written.
  - `logger` is a `fun interface` receiving direction, frame and a monotonic timestamp. M2 maps it to the `BMAP` log tag. No Android imports.

### 2. Device config as data

- `Address(fblock, func)`. `Readable<T>(address, parse)` and `Writable<T>(address, parse, build)`.
- `object QcUltra2`: one entry per feature-map row. Pairing [4.8] and power off [7.4] are START-only entries. [1.4] and [31.4] are absent.
- A typed facade, `Headphones(connection, config)`: `read(feature)`, `write(feature, value)` (returns the STATUS reply), `deviceInfo(mac)`, `allModes(): ModesSnapshot` (one drain → modes plus the current mode, favourites and audio settings, when present), `selectMode(idx): AudioSettings` (START 31.3 `[idx, 0]`, then GET 31.10, per review note 2), `pairingMode()`, `powerOff()`.

### 3. Parsers and builders (`Parsers.kt`, `Builders.kt`, models in `Models.kt`)

Parsers are strict: if a payload is too short, they throw `BmapException.Malformed(address, payload)`. They never return defaults, so the UI never shows made-up values as real.

| Addr | Model | Source and notes |
|---|---|---|
| 0.5 | firmware `String` | ASCII |
| 1.2 | product name | skip flag byte; build: UTF-8, max 31 bytes, rejected (not truncated) above |
| 1.7 | `Eq(bands)` with signed min/max/current | build `[value, bandId]`, -10..10 |
| 1.9 | `ButtonMapping(buttonId, event, action, raw)` | read only, no name tables |
| 1.10 | `Multipoint(enabled = bit 0x02, raw)` | parse only, no builder in M1. M2's hardware test explores the write |
| 1.11 | `SelfVoice(persist, level, raw3)` level off/high/medium/low | GET returns 3 bytes (`01 02 0f`); third kept raw, probably the supported-levels mask (unverified). Build `[1, level]` (bosectl); persist flag hidden in the UI |
| 1.24, 1.27 | bool | build `[0/1]` |
| 2.2 | battery percent (byte 0) | |
| 4.4 | `PairedDevices(header, macs)` | inferred from the fixture: 1 byte then 6-byte MACs (bosectl has no parser) |
| 4.5 | `DeviceInfo(mac, flags 3 B raw, name)` | inferred from the fixture; request payload = MAC |
| 5.1 | `Source(type, mac?)` | bosectl `parse_source` |

### 4. Profile logic (`Profiles.kt`, ported from bosectl `connection.py`)

The decision logic is pure functions over `List<ModeConfig>`, and suspend wrappers on `Headphones` call them:
- `findFreeSlot`: the first slot in 4..10 whose name is blank or `None`, ignoring the configured bit (bosectl `_find_free_slot`).
- `validateName`: not blank, at most 31 UTF-8 bytes, not `None`, and not a preset name in any case (built-in names plus any non-editable slot's name, as bosectl `_refuse_preset_name` does).
- `findProfile`: by name, case-insensitive, editable slot first.
- `create`, `update` (keeps prompt bytes, rename re-validates) and `delete` (writes `None` with zeros, as bosectl does). Each one refuses slots 0..3 and returns the 40 B write. `Headphones.createProfile/updateProfile/deleteProfile` drain, plan, then SETGET 31.6.
- Full slots throw `ProfileError.NoFreeSlot`. Errors are a sealed type, so M4 can show clear messages.

### 5. `FakeBmapDevice` (`bmap/src/testFixtures/kotlin/...`)

- It implements `FrameTransport` and parses written bytes with `FrameParser`.
- Its state is per-address raw payloads, seeded from the M0 fixture files, so GET replies match the device byte for byte.
- Behaviour copied from M0:
  - START 31.3 sets the current mode and copies that mode's cnc/autoCnc/spatial/wind/anc into 31.10. A code comment says this is inferred from one observation (M0 E5).
  - SETGET 31.10 with autoCnc 1 → ERROR 8.
  - SETGET 31.6 on slots 0..3 → ERROR 8. On slots 4..10 it rebuilds the 48 B STATUS.
  - START 31.1 replays PROCESSING, the fblock-31 STATUS frames from current state, then RESULT, in fixture order.
  - [1.4] → ERROR FuncNotSupp. [31.4] → silence.
- Fault injection: per-address delay or silence, PROCESSING before the reply, unsolicited frames, garbage bytes, replies split into chunks or several replies in one chunk, drop the drain's RESULT, disconnect (`read()` returns null), and throw `IOException`.
- It records every frame received. Tests assert none is SET or fblock 18.
- The fixtures move from `src/test/resources` to `src/testFixtures/resources` (git mv, contents unchanged). The fake and M3's debug demo mode can then load them from the classpath. `FixtureParseTest` keeps working through the classloader.

## Tests (JUnit 6 + `runTest` virtual time)

- `ParsersTest`: every parser against its fixture, with the expected values written out (battery 80, firmware `10.12.12+ga927c9a`, EQ 3 bands -10..10 at 0, Self Voice medium, multipoint on, 11 modes Quiet..Run plus 3 × None, current mode 2, favourites {0,1,2,4,6,7}, 31.10 = anc on, spatial 2). A malformed or short payload throws.
- `BuildersTest`: 31.10 and 31.6 byte layouts, name padding, signed EQ, a 31-byte multibyte name accepted and 32 bytes rejected.
- `ProfilesTest`: free slot = 8 on the fixture state, full slots, preset names in any case, slots 0..3 refused, update keeps prompt bytes, delete payload, rename validation.
- `BmapConnectionTest` against the fake:
  - matching: GET, byte-by-byte and multi-reply chunks, stray frame before the reply (goes to unsolicited), PROCESSING then STATUS, ERROR code
  - timeouts and drain:
    - timeout, then a successful retry
    - one silent address while the rest answer: `Unsupported`, connection stays open
    - everything silent: `Timeout` and `Closed(Unresponsive)`
    - power off and pairing: the disconnect counts as success, with no retry
    - drain ends on RESULT well under 500 ms (virtual clock)
    - drain silence fallback
    - repeated address in a drain: the last value wins
    - non-31 frame during a drain goes to unsolicited
  - link: garbage skipped; disconnect mid-request gives `Disconnected` and `Closed(RemoteClosed)`; IOException gives `IoError`; SET and fblock 18 refused with nothing written; 10 concurrent requests all answered one at a time
  - `Headphones`: `selectMode` returns the new 31.10 values (spatial 02 → 00 as in E5); create, update and delete a profile end to end on the fake
- `FakeFixtureTest`: every fixture request, sent to a fresh fake, gets back exactly the fixture reply.
