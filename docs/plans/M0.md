# M0 plan: spike and device truths

Status: approved by reviewer 2026-10-27 with changes (folded in below).

Branch `m0-spike`. One PR into `main` at the end.

## Context

M0 answers the protocol unknowns before M1 builds the real library: which RFCOMM connect path works on Android 17, what the headphones send on connect, whether commands need spacing, whether anything arrives unsolicited, whether the headphones can be kept awake past the 10-minute idle sleep, and real payloads for every feature address as test fixtures. It also proves the debug-build screen workaround for the 5-minute screen lock policy.

## Build

### Gradle skeleton

- `settings.gradle.kts`: plugin repos, `include(":bmap", ":app")`.
- `gradle/libs.versions.toml`: versions above.
- Root `build.gradle.kts`: plugins declared `apply false`.

### `:bmap` (pure Kotlin/JVM, zero Android imports)

- `BmapOp` enum (0..7) and `BmapFrame(fblock, func, op, payload, deviceId = 0, port = 0)` with `encode()`. Port of `bmap_packet` / `parse_response` in `reference/bosectl/python/pybmap/protocol.py`.
- `FrameParser`: streaming. `feed(bytes): List<FrameEvent>` keeps a buffer across reads; emits complete frames; handles partial frames, several frames per chunk, zero-length payloads.
- **Resync:** BMAP has no sync byte. A frame start is accepted only if the op nibble is 0..7 and the fblock is one the device is known to use (0–9, 18, 31; NOTES.md function block map). Otherwise drop one byte, emit `Skipped(bytes)` and retry. Consecutive dropped bytes are reported together so every resync is logged with its bytes. RFCOMM is reliable and in order, so junk is only expected around connect. Revisit after E2/E4.
- `Hex` helpers (format/parse, spaced lowercase).
- Unit tests (JUnit 6): round-trip encode/parse, flags with deviceId/port, partial across 2–4 chunks, byte-by-byte feed, multiple frames in one chunk, zero-length payload, 255-byte payload, resync on invalid op and on unknown fblock, trailing partial kept for the next feed, fixture files all parse cleanly (once captured).

### `:app` (namespace and applicationId `io.github.sargemck.practicalheadphones`, minSdk 31, compile/target 37)

- `src/main`: minimal `MainActivity` (Compose, Scaffold, title only) so release has a launcher and the VS Code task's `.MainActivity` is valid. Manifest: `BLUETOOTH_CONNECT` only. No `INTERNET`.
- `src/debug` only (release builds contain none of this):
  - `SpikeActivity`, `launchMode=singleTop`, sets `FLAG_KEEP_SCREEN_ON`, `setShowWhenLocked(true)`, `setTurnScreenOn(true)`. Commands arrive as intent extras through `adb shell am start -n <pkg>/.SpikeActivity --es cmd ...` (`onCreate` / `onNewIntent`). Shows a plain text log on screen for screenshots.
  - `SpikeSession` (process-wide object, own coroutine scope, survives activity recreation): holds one socket and one reader coroutine. The reader feeds `FrameParser` and logs every frame. `read() == -1` and `IOException` are both treated as a disconnect, and the log says which one happened.
  - Commands:
    - `connect --es path sdp|reflect`: finds the bonded device by name containing "QC Ultra 2", cancels discovery, connects. Logs path and time taken. For SDP, tries to log the landed channel via the hidden `BluetoothSocket.getPort()`; if hidden-API rules block it, logs "unknown" and relies on BMAP replies as proof.
    - `probe2`: one-shot second socket while the first is open; logs the result or error and closes it.
    - `send --es hex "02 02 01 00"`, `latency --ei n 20`, `burst --ei n 10 --ei gap 0`, `heartbeat --ei every 60` / `heartbeat --ei every 0` (stop), `dump` (GET every feature address), `writes` (E5 timed writes), `close`.
  - `SafetyGuard` is an **allowlist**. Allowed in M0:
    - GET on any address except fblock 18
    - START only on 31.1 and 31.3
    - SETGET only on 31.10

    Everything else is refused and logged, including through `send`.
  - Reply matching (spike-level, not M1's `BmapConnection`): a request completes on the first frame with the same `(fblock, func)` and op STATUS/RESULT/ERROR. PROCESSING keeps waiting. 3 s timeout. No fixed waits for replies. `burst --ei gap` is an explicit test parameter, not a wait.
  - Logging tag `BMAP`: `OUT`/`IN` + `SystemClock.elapsedRealtime` in ms with 3 decimals + spaced hex. Raw read chunk sizes are also logged. At session start (`SpikeSession` init and every `connect`) it logs wall-clock time and `elapsedRealtime` together, so our timestamps line up with Bluetooth's.
  - `SilentAudioService` (debug only, foreground type `mediaPlayback`, AudioTrack writing zeros). **Built only if experiment 0a fails.** Declares `FOREGROUND_SERVICE_MEDIA_PLAYBACK` in the debug manifest, starts only while SpikeActivity is in front (Android 17 restricts background audio for apps targeting 37), and doesn't request audio focus.
- Install with `adb install -r -g app/build/outputs/apk/debug/app-debug.apk` (`-g` grants `BLUETOOTH_CONNECT` without a tap).

## Device session (hands-off)

**Start-of-run** (scripted):

1. `adb devices` shows the phone.
2. `adb logcat -G 16M`, then stream `adb logcat -v threadtime` to a file in the scratchpad for the whole session.
3. Headphones A2DP connected (`dumpsys bluetooth_manager`).
4. `am force-stop net.quietrebellion`.
5. Screenshot to confirm the phone is unlocked.

Order is chosen so quick work fits inside one 10-minute wake window.

Writes in M0: only E5 (START 31.3, SETGET 31.10).

## Fixtures and redaction

- Location: `bmap/src/test/resources/fixtures/qc-ultra2/fw-<version>/<fblock>.<func>-<op>.txt`, one request/reply exchange per file: `> 02 02 01 00` / `< 02 02 03 04 50 ff ff 00`.
- Redacted before committing, keeping byte lengths so frames still parse: MACs (bytes replaced, format kept), headphone name and paired-device names (same-length filler), serials. Every redaction is listed in `fixtures/README.md` (file, offset, what it was).
- Every fblock 0 reply is checked for a serial. 4.4 and 4.5 replies contain other devices' MACs and names: redacted.
- Raw unredacted logs stay in the scratchpad, outside the repo.
- A unit test parses every fixture through `FrameParser` (proves the redacted files are still valid frames).
