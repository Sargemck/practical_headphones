# M3 plan: main UI

Branch `m3-ui`. First commit (`Apply M2 review notes`, pushed) applies the M2 review. One PR into `main` at the end.

## Context

M2 gave us a tested `HeadphoneRepository` with `StateFlow<HeadphoneState>`, optimistic writes and a foreground service. M3 builds the one screen people use, on top of that state. It fixes Quiet Rebellion bugs:
- bug 3: title under the status bar
- bug 4: Power Off text cut off
- bug 5: jargon with no explanations

It adds an About screen, the licence files and a debug demo mode. The UI only observes state and calls repository actions; no protocol logic moves into it. H1 (by ear, by hand) follows S1 and checks what screenshots can't.

## Design

### 1. Wiring (UI ↔ service)

- `HeadphoneController` interface: `state`, `messages`, and the actions. `HeadphoneRepository` implements it.
- `AppGraph`, a process singleton, holds `StateFlow<HeadphoneController?>`. The service sets it in `onCreate` and clears it in `onDestroy`. `MainActivity` collects it. Same process, no binder needed.
- Composables take a plain `HeadphoneState` plus an `Actions` object of lambdas. Screens are pure functions of state, so screenshot tests need no repository.
- **Demo mode (debug only):**
  - `adb shell am start ... --ez demo true` gives `MainActivity` a `HeadphoneRepository` whose connector returns a `BmapConnection` over `FakeBmapDevice`, with the system link reported connected. The service isn't started and the headphones aren't touched.
  - `src/debug/DemoMode.kt` builds it via `debugImplementation(testFixtures(project(":bmap")))`.
  - `src/release/DemoMode.kt` returns null, so release builds have no fake and no fixtures.

### 2. Screen

- `Scaffold` with `TopAppBar` (app name, About action), edge-to-edge with insets (fixes bug 3), and a `SnackbarHost` for `UserMessage`s.
- One `LazyColumn` of section cards. While not `Connected`, a status card replaces the sections:
  - it explains the link state in plain words
  - "Reconnect" for `AnotherApp`, `ConnectFailed` and `Lost`
  - "Open Bluetooth settings" for `BluetoothOff` and `NotPaired`
- Each section renders its own `Section<T>`:
  - `Loading`: a placeholder with a progress indicator
  - `Failed`: "Couldn't read this" with "Try again", which calls the new `retryFailed()`
  - `Unsupported`: section hidden
- Bose app banner, when `boseAppInstalled`: "The Bose app can take over the connection. If this app stops responding, force stop the Bose app." Button: "Open Bose app settings" (`ACTION_APPLICATION_DETAILS_SETTINGS`).
- About is a second screen (simple screen state plus `BackHandler`, no navigation library). It shows:
  - app version and headphone firmware
  - MIT licence
  - bosectl credit ("Protocol knowledge from bosectl, MIT, Copyright (c) 2026 Aaron Bockelie", with link)
  - "Not affiliated with Bose"
- Every control gets a `testTag`, with `testTagsAsResourceId = true`, so adb can drive it by resource id.
- No fixed heights or widths on text containers. Buttons and labels wrap (fixes bug 4).

### 4. Repository additions (small)

- `setEq(bass, mid, treble)`: one optimistic change, three band writes in order (the device takes one band per SETGET); rolls back as one.
- `retryFailed()`: re-reads every `Failed` section once.
- `toggleFavourite(index)`: builds the new `Favourites` from cached state, then `setFavourites`.

### 5. Licence files

`LICENSE` (MIT) and `NOTICE` (bosectl credit and MIT text) at the repo root. The About screen shows the same text (Q2).

## Tests

**Screenshot tests** (Robolectric + Roborazzi, `app/src/test`):
- one per section, plus the full screen, each in light, dark and font scale 2.0 (the largest on Android 14+)
- the status card for each link state, the Bose banner, loading and failed sections, the rename, pairing and power-off dialogs, and About
- States are built from the M0 fixtures (`Fixtures` + `Parsers`), so they show real values.
- Goldens are committed under `app/src/test/screenshots/`. `./gradlew test` verifies against them (`roborazzi.test.verify=true`); `./gradlew recordRoborazziDebug` re-records. I check every PNG myself, and the PR shows them.

**Compose behaviour tests** (Robolectric):
- slider position maps to `10 - cnc` both ways
- tapping a preset calls `setEq` with its values
- the star toggles the favourite
- rename rejects blank or more than 31 bytes and trims
- power off and pairing mode only fire after confirming
- **no text overflows** at font scale 2.0: walks every text node and asserts the layout has no visual overflow (covers bug 4)

**Unit tests:** `setEq` (optimistic, three writes, rollback as one), `retryFailed`, `toggleFavourite`, `EqPreset.match`.

## Hands-off device run (desk setup only)

0. Start checks; wake with a spike connect if asleep. Take a `STATE` snapshot as the baseline.
1. Install the debug build and launch it. Screenshot the loaded screen, then dark mode (`cmd uimode night yes`, then restored).
2. Drive every control by resource id (uiautomator, `input tap` / `swipe`), screenshot after each, and confirm each write by the device reply in logcat:
   - mode switch and favourite star (toggled back)
   - slider, Wind Block, noise cancelling, spatial Off / Still / Motion
   - each EQ preset and a custom slider
   - Self Voice levels, auto answer, auto play/pause
   - rename to "PH Test" and back
3. Power off and pairing mode: open the dialogs, screenshot, Cancel. Never confirm.
4. Restore everything and compare the final `STATE` dump with the baseline.
5. Demo mode: launch with `--ez demo true` and screenshot it, to show the PR the same screen without the headphones.

Device screenshots in the PR are cropped to our app.
