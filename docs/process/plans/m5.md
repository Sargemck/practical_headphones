# M5 plan: Quick Settings tile

Branch `m5-tile`, based on `m4-modes` (#7). Implemented straight after the plan, per Sargemck's 2026-11-03 instruction.

## Behaviour

- **Label and subtitle.** Connected with modes loaded: the label is the current mode ("Quiet"), the subtitle is what a tap does ("Next: Aware").
  - No starred mode to go to: the subtitle says "Star modes to cycle", and a tap does nothing.
  - Not connected, or the service isn't running: the tile is unavailable (greyed). The label is "Headphones", the subtitle is the link state ("Not connected", "Another app is using your headphones", …).
  - Connected but still loading: inactive, "Loading…".
- **Tap:** next starred mode, the same as the headphones' button and the notification action (`nextFavourite`).
- **Long-press:** opens the app (`QS_TILE_PREFERENCES` on `MainActivity`).
- **Updates:** live while the shade is open. The tile watches the service's state between `onStartListening` and `onStopListening`, and nothing runs otherwise.
- **App closed:** the tile talks to the running service through `AppGraph`, the same process. If the service isn't running, it stays unavailable. M6 starts the service on presence, and until then the service runs once the app has been opened.
- **Adding the tile:** on Android 13+, the All modes sheet has "Add to Quick Settings" (`StatusBarManager.requestAddTileService`). It's hidden once the tile is added (`onTileAdded` / `onTileRemoved` keep a flag).

## Code

- `tile/TileModel.kt`: a pure `TileModel.from(controllerPresent, state)`, unit tested like `NotificationModel`.
- `tile/ModeTileService.kt`: the `TileService`.
- Manifest:
  - the service, with `BIND_QUICK_SETTINGS_TILE` and the QS_TILE intent filter
  - the preferences intent filter on `MainActivity`
- `HeadphoneController` gains `nextFavouriteMode()` (the repository already has it).
- UI: `canAddTile` flag, `Actions.addTile`, and the row in the sheet.

## Tests

- **JVM:** `TileModelTest` covers every link state, loading, no favourites, and the wrap-around to the next favourite.
- **UI:** the add-tile row shows only when `canAddTile`, calls `addTile`, and has a golden.
- **Device run (hands-off):**
  - `adb shell cmd statusbar add-tile <component>`
  - `cmd statusbar click-tile <component>` with the app in the background (`am kill`, not force-stop, then the service restarted from a launch)
  - confirm the mode change by read-back
  - screenshot the shade
  - `cmd statusbar remove-tile` afterwards

## Risks

- **R1.** `click-tile` may need the shade expanded on Android 17. Fallback: `cmd statusbar expand-settings` and an `input tap` on the tile's bounds from `uiautomator dump`.
- **R2.** A tap while the shade is locked: Android asks to unlock first, by default for tiles that aren't `isSecure`. Acceptable, since mode switching isn't sensitive. Kept the default.
