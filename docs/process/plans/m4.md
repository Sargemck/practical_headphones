# M4 plan: custom mode editor and permission states

Branch `m4-modes`, based on `m3-about-fix` (PR #5, the UI pass), because the editor builds on its modes card and All modes sheet. One PR into `main`, after #5 and #6.

Baris asked (2026-11-03) for every remaining milestone to be implemented without waiting for approvals, so this plan and the code ship in the same PR. H1 hasn't run, so its fix list isn't in M4. The two reviewer UX notes for H1 (preset tag, top-bar scroll) already shipped in #5.

## Scope

1. **Create a mode.**
   - "New mode" in the All modes sheet opens the editor.
   - It starts from the current noise settings, so "save what I hear now" is one name and one tap.
   - Save writes [31.6] to the first free slot (4–10), then switches to the new mode.
   - All slots full: the sheet says so instead of offering "New mode" ("All 7 custom modes are in use. Delete one to add another.").
2. **Edit, rename and delete a custom mode.**
   - An edit button on each custom mode in the sheet opens the editor.
   - Presets 0–3 have no edit button and keep the "Bose preset" tag.
   - Saving the current mode switches to it again, so the change is heard at once. Fw 10.12.12 isn't known to reload [31.10] when the current slot is rewritten.
   - Delete asks first. Before the delete write:
     - if the mode is current, switch to Quiet (slot 0)
     - if it's starred, remove it from favourites, so the button never cycles to an empty slot
3. **Editor screen.**
   - Fields: name, noise slider (same as the main screen), Wind Block, noise cancelling, spatial chips.
   - Save in the top bar, enabled only when the name is valid and something changed.
   - Name errors show inline:
     - blank
     - over 31 UTF-8 bytes
     - "None" (reserved for empty slots)
     - a Bose preset's name
     - a name another mode already has (new: bosectl doesn't check this)
4. **Writes.**
   - Optimistic, per the Android rules: the list updates at once, then the change is sent.
   - Every create, edit and delete ends with a fresh [31.1] drain, so the list, current mode, favourites and audio come from the device.
   - Failure rolls back to the list before the change and shows a snackbar.
   - Slot choice and the voice prompt bytes come from a fresh drain inside `Headphones`, not from the cache, so another app's changes are never overwritten.
5. **Permission states (M3 review Q1).**
   - Without `BLUETOOTH_CONNECT`, the hero card says "Allow Nearby devices" with an Allow button.
   - Once Android won't show the prompt again, the button becomes "Open settings" (app details).
   - Without `POST_NOTIFICATIONS`, a dismissable banner explains what's missing (the mode controls in the notification) and offers the same buttons.
   - Granting in settings is picked up on return (`onStart` re-checks).
6. **Favourites byte order (hands-off device run).**
   - Create a test mode, which lands in the first free slot (8 on Baris's headphones).
   - Star it, read [31.8] back, and confirm the bit lands where the parser says.
   - Restore favourites, delete the test mode, and compare a before/after snapshot of all modes.

## Code

- `:bmap`:
  - `Profiles` gains index-based `update` and `delete`
  - `validateName` returns a typed `NameProblem` and checks duplicates, with an `except` slot for renames
  - `Headphones` gains `updateMode(index, …)` and `deleteMode(index)`
  - the name-based bosectl ports stay
- `HeadphoneRepository` gains `createMode`, `updateMode` and `deleteMode` (`HeadphoneController` too). Each keeps the `Modes` write guard, so a poll can't undo the optimistic list.
- UI:
  - `Screen.ModeEditor`, a `ModeEditor` composable, and the sheet changes
  - a `PermissionState` passed from `MainActivity`
  - hero and banner copy

## Tests

- **JVM:** `ProfilesTest` covers the index-based update and delete, the duplicate check and the `NameProblem` mapping.
- **Repository against `FakeBmapDevice`:**
  - create → switches to the slot and the drain shows it
  - edit of the current mode re-selects it
  - delete of the current starred mode → Quiet, star removed, slot `None`
  - full slots → message, nothing sent
  - a failed write rolls back
- **UI:**
  - editor validation messages
  - Save enabled state
  - delete confirm
  - "New mode" hidden when full
  - permission hero and banner
  - no overflow at font scale 2
  - goldens for the editor (new and edit) and the permission states
- **Device run (hands-off):**
  - create, edit, switch to and delete a test mode, each confirmed by read-back
  - the favourites byte-order check
  - Baris's modes compared before and after

## Risks

- **R1.** The real [31.6] SETGET reply shape is unverified (the fake echoes the 40 bytes, as bosectl expects). The fresh drain after each write makes the reply shape irrelevant to state.
- **R2.** Deleting the current mode without switching first is untested on the device. Switching to Quiet first avoids the question.
- **R3.** Rewriting the current slot may not reach [31.10]. Re-selecting the mode after save covers it. The device run checks whether it's needed.
